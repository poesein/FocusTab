# FocusTab · 专注

一个面向中文科研浏览的独立 Chrome / Edge 扩展，把三件事放在一起：**新标签页、页面内容判断、热点与分心内容拦截**。

项目源码：[poesein/FocusTab](https://github.com/poesein/FocusTab)。这是基于 LeechBlock NG 仓库建立的独立扩展目录，使用单独的 Manifest 和界面。无需 ActivityWatch、本地统计服务或桌面软件运行记录，也不依赖原版 LeechBlock 扩展。

## 三种功能

| 功能     | 实际行为                                                                                                                                               |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 新标签页 | 中文搜索与研究目标入口、研究计时、可拖动排序的快捷入口、外观和文字设置。                                                                               |
| 内容判断 | 只判断点开后的最终网页；无任务时自动区分工作/主动学习与娱乐，有研究任务时同时参考其目标。Google 等搜索结果页不送 AI。                                  |
| 拦截     | 浏览器 `declarativeNetRequest` 规则优先拦截热点入口；AI 默认拦截高置信度的娱乐或偏离页面，也可选择仅提醒。支持自定义域名与路径规则、当前页面短时放行。 |

默认规则拦截科研通 `/tophot`、今日热榜全站，以及 B 站、知乎、YouTube、X 的主要推荐与热点入口。科研通首页和文献功能保留，具体视频与问答页面按内容分析。主动搜索娱乐内容不会使它自动成为研究白名单。默认研究计时 25 分钟，到期发出提醒，用户可以续时；自动模式会继续判断内容，关闭自动模式时则只在有效研究任务内判断。计时到期不会强行关闭查资料页面。热点入口的短时放行到期后恢复规则拦截。

从旧版本升级会保留已保存的“仅提醒”等显式设置；需要内容拦截时，请在“内容判断”中确认选择了高置信度拦截。

工具栏面板会重新读取最近的普通浏览器窗口，显示当前页面与实际版本；“运行信息”可查看拦截方式、请求用量和页面检测原因。重新识别页面不请求 AI，不消耗 NAS 判断额度。浏览器未在前台或电脑空闲时，可以显示最近普通网页的清理后标题/网址，但不进行内容判断；无痕与内部页面不会作为判断输入。

具体规则以 `src/rules.mjs` 为准。网站改版或新的推荐入口可能需要补充路径，规则不能保证识别所有同类页面。

## 安装到 Edge / Chrome

需要 Chromium 120 或更新版本。安装解压后的 `dist` 文件夹即可，不需要 Node.js。源码使用者先按下方步骤构建。

1. 把 `dist` 放到一个以后不会随手删除的目录。更新时覆盖同一目录并在扩展管理页面点击重新加载。
2. 打开 `edge://extensions` 或 `chrome://extensions`，开启“开发人员模式”。
3. 选择“加载解压缩的扩展”，选择 `dist` 文件夹，确认安装。新标签页被替换时，选择保留更改。
4. 打开新标签页的设置，确认 AI 地址、模型、需要分析的站点和拦截方式。
5. 先测试科研通首页可访问、`/tophot` 被拦截、具体视频/问答可访问，再开始一项明确的研究任务并测试 AI。

Manifest 内置固定的公开扩展密钥，使解压安装的 ID 为 `lnnnhlfmngbblnidaodogogceicokpnj`，复制到另一个目录或后续更新时仍使用此 ID。这里仅提交公钥，构建不需要私钥；它用于稳定身份，不代表商店签名或开发者身份认证。不同浏览器/配置文件的本地存储仍各自独立，请以扩展管理页显示的实际 ID 为准。

原有 LeechBlock 仍启用时，两个扩展会分别执行自己的规则。请先完成新扩展实测，再手动停用旧插件和旧专注助手；本项目不会自动卸载、停用或修改它们。若旧扩展受浏览器策略管理，需要在其管理来源调整，无法由新扩展直接移除。仅加载新插件不会停止原有 ActivityWatch 采集服务；如不再使用，应在验证迁移后另行停用原服务。

扩展安装、浏览器对权限的确认和 NAS 配置都需要用户在相应界面完成。仓库中的自动测试与网页预览不能代替浏览器内的安装验收。

## AI 连接与资源控制

默认地址 `http://127.0.0.1:11434`，模型可选择 `qwen3:8b` 或 `qwen3:14b`。模型需要已存在于该 Ollama 服务；扩展不自动下载模型。地址只接受本机或局域网 IPv4 / `localhost` 的 HTTP(S) 源，不接受公网服务、带账号的 URL、额外路径或查询参数。

NAS 同时处理科研任务时，可使用省资源预设，减少请求频率、每小时上限和模型驻留时间。预设不代表在该 NAS 上完成了性能测试，实际响应速度与可用内存应以面板连接测试和服务监控为准。默认值为停留约 20 秒后分析、间隔 90 秒、每小时最多 12 次，结果缓存 30 分钟；手动检查也受预算限制。切换页面、研究任务结束或设置变化时，旧结果不会继续应用到新页面。

出现 `403` 时，先在面板确认实际扩展源，再由 NAS 管理员检查 Ollama 的 `OLLAMA_ORIGINS`。本构建的来源为 `chrome-extension://lnnnhlfmngbblnidaodogogceicokpnj`。**只增加当前扩展的准确来源，保留已有必要来源，不要改成 `*` 或 `chrome-extension://*`。** 此扩展不会修改 NAS 环境变量或重启服务。自行更换 Manifest 公钥或使用其他发行身份时，来源许可需要相应更新。

若 `/api/tags` 对扩展来源返回 `403`，需要先解决来源许可才能验收 AI。下面仅展示要追加的单项环境变量，不是完整 Docker Compose 文件，也不应覆盖现有 Compose 或删除已有许可来源：

```yaml
environment:
  # 将 EXISTING_ALLOWED_ORIGINS 替换为当前真实值；当前为空时只填准确扩展源。
  OLLAMA_ORIGINS: 'EXISTING_ALLOWED_ORIGINS,chrome-extension://lnnnhlfmngbblnidaodogogceicokpnj'
```

如果现有配置采用 `- KEY=value` 列表写法，应沿用原文件格式，只更新 `OLLAMA_ORIGINS` 这一项。**配置变更通常需要重启/重建 Ollama 服务才会生效，可能中断 NAS 上其他 AI 科研任务。** 应由服务管理员在任务空闲时操作。配置示例中的占位文字不得直接原样当作许可来源使用。

连接失败、超时、模型缺失、返回格式错误或相关性不明确时，页面继续保留，面板显示问题；域名/路径规则仍然独立生效。AI 是辅助判断，不能可靠推断所有研究意图，尤其是只有很少文字的视频页面。

## AI 获得了什么

在用户设置的分析站点中，扩展读取**当前活动标签页的标题和 URL**。Google、Bing 等检索结果页不参与 AI 判断；只有打开最终内容页后才判断。发送前清理 URL 的账号部分、查询参数和片段；YouTube 视频 ID 在需要区分视频时保留。

可选择两种内容输入：

- **仅页面信息**：研究任务、清理后的 URL、标题。
- **正文摘要**：上述信息加 Mozilla Readability 从当前页面副本提取的文字摘录，默认最多 1,800 字符；无法提取正文时使用页面描述。

提取前去掉表单、输入框、可编辑区域和常见导航等元素，不读取表单填写内容。不会录屏、截图、读取浏览历史、下载视频/音频、识别视频画面或转写声音。B 站、YouTube 视频页优先使用标题、简介与标签，排除右侧推荐和评论，避免把旁边的娱乐推荐误当成当前科研视频内容。它不能像人一样“看见整个窗口”。

默认分析名单只含指定公共网站；账号、私信、支付和若干个人页面路径会排除。用户自行添加的站点仍应谨慎选择。标题、公开页面正文和 URL 路径也可能包含敏感信息，正文摘录的邮箱遮盖不等于完整匿名化。发送目标是用户设置的 Ollama 服务；NAS 是否记录请求及其保留策略由该服务决定，扩展无法控制其服务端日志。

## 新标签页与浏览器界面

新标签页通过原生 `chrome_url_overrides` 直接加载扩展本地页面，不跳转到本机 HTTP 服务。浏览器书签栏的显示仍由浏览器设置决定；项目不修改原生书签栏偏好，也不读取或复制书签。部分 Chromium 浏览器对自定义新标签页与“仅在新标签页显示”模式存在兼容差异，普通扩展 API 没有原生书签栏显示开关，因此不能承诺通过网页样式控制该模式。

本地网页预览会隐藏 RSS+ 用户脚本追加到专注页外部的组件，以避免其受 CSP 限制后暴露原始设置面板；这条样式仅作用于专注页面，不修改用户脚本本身或其他网站。

## 设置、反馈与保存

- `chrome.storage.local`：设置、当前研究任务、用户明确提交的判断反馈。
- `chrome.storage.session`：临时页面状态、调用预算、缓存和短时放行等运行数据。浏览器关闭后通常清除，扩展服务工作进程休眠不会当作全新使用周期。
- 反馈最多保留 200 条，默认 90 天，可在设置中调整保留期限并清除。反馈纠正当前任务/相同页面的判定，只有明确选择记住的记录才跨任务复用；它不会训练 NAS 模型、修改模型权重或创建模型训练数据集。
- 不启用云同步，不把反馈自动上传到 GitHub，不保存完整正文或浏览历史列表。设置页支持导出/导入设置，备份不包含研究目标、正文或反馈。重装或卸载扩展可能丢失本地配置，请先导出需要保留的自定义设置。

## 权限说明

| 权限                        | 用途                                                                                                                           |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `tabs`、`webNavigation`     | 识别活动标签页与页面内部导航，在明确拦截时跳转到说明页。                                                                       |
| `storage`                   | 保存设置、任务与显式反馈；使用会话存储保存临时状态。                                                                           |
| `alarms`、`idle`            | 运行限频检查、到期提醒、用户闲置时停止分析。                                                                                   |
| `scripting`                 | 在需要摘要且页面被允许分析时，注入本地打包的提取器。没有常驻全站内容脚本。                                                     |
| `notifications`             | 提醒研究计时到期或页面可能偏离任务。通知是否展示还取决于系统/浏览器设置。                                                      |
| `declarativeNetRequest`     | 使用浏览器原生规则拦截主框架页面请求。                                                                                         |
| `http://*/*`、`https://*/*` | 支持用户自定义屏蔽站点、页面提取和可配置局域网 AI 地址，因此安装时会出现较宽的站点权限提示。实际分析受站点名单与路径排除控制。 |

无隐私窗口支持、无 `history` 或 `desktopCapture` 权限、无 `externally_connectable`。为浏览器拦截重定向提供的 `blocked.html` 及共用脚本/CSS 被列为 web-accessible resources；网站可能请求这些公开资源并探测安装状态。扩展不信任页面提供的参数，也不接受普通网站发来的特权消息。浏览器内置页面、扩展商店等受保护页面无法被普通扩展注入或统一接管。

全部运行代码、样式和依赖在构建时打包到本地，无 CDN、远程脚本或动态 `eval`。

## 开发与构建

需要 Node.js 22 或更新版本和 npm。所有命令在 `focus-tab` 目录运行：

```sh
npm ci --no-audit --no-fund
npm test
npm run build
npm run preview
```

`npm run build` 生成独立的 `dist/`，包括 Manifest、三种页面、后台工作进程、正文提取器、原创图标和运行依赖许可证。构建基于锁文件固定版本，不需要安装原版 LeechBlock 所用的 jQuery。

公开源码与 CI 使用本机 Ollama 默认地址。NAS 地址可安装后在设置中填写；若需要个人安装包预填地址，可在本机构建环境设置 `FOCUSTAB_AI_HOST` 后再构建，生成文件保持在被 Git 忽略的 `dist/` 中。不要提交包含个人网络配置的定制构建或设置备份。

`npm run preview` 只在 `http://127.0.0.1:5668/` 提供静态界面。**这是界面预览；拦截、浏览器权限和 AI 在该预览中不生效。** 预览不代理或调用现有 ActivityWatch、FocusCompanion 或 NAS 服务。可用环境变量 `FOCUSTAB_PREVIEW_PORT` 更换本地端口。真实浏览器插件功能必须加载 `dist` 验收。

| 入口                         | 文件                                   |
| ---------------------------- | -------------------------------------- |
| 页面与样式                   | `src/app.jsx`、`src/app.css`           |
| 页面 / 扩展通信和预览适配    | `src/bridge.mjs`                       |
| 默认参数与校验               | `src/config.mjs`                       |
| 后台事件与状态机             | `src/background.mjs`、`src/engine.mjs` |
| 网址规则、结果校验与反馈匹配 | `src/rules.mjs`                        |
| AI 请求                      | `src/ai.mjs`                           |
| 正文提取                     | `src/extract.mjs`、`src/extractor.mjs` |
| 构建和本地预览               | `scripts/`                             |

CI 在 `focus-tab` 源码或工作流变更时运行 `npm ci`、测试和构建，然后上传 `dist` ZIP 构建产物；不自动发布商店版本。自动测试覆盖可测逻辑，仍需在目标 Edge / Chrome 中测试扩展安装、DNR 拦截、SPA 导航、通知和真实 Ollama 连通性。
